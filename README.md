# magic_share — project_stat демо-стенд

Локальный автономный стенд учёта паркетной фабрики. Показывает, где цех
теряет деньги: собирает отчёты участков → считает материальный баланс →
находит 3 узких места → локальная LLM (Qwen2.5-1.5B-Instruct) объясняет результат
по-русски. Всё на обычном компьютере, без облаков.

## Для коллеги (итоговый запуск)

Если вы уже выполнили скилл `magic_share.md` через opencode — просто
запустите стенд:

- **Windows:** откройте папку `project_stat\` в проводнике и дважды
  кликните `run.bat` (или в терминале: `project_stat\run.bat`).
- **macOS / Linux:** в терминале `bash project_stat/run.sh`.

Откроются 4 окна в сетке 2×2:

| Окно | Что это |
|------|---------|
| Проводник (`test_reports`) | входящие CSV-отчёты участков |
| STAT_WATCHER | наблюдатель: парсит CSV → БД → аналитика |
| Браузер (`127.0.0.1:8770`) | статистика + заключение LLM |
| STAT_GEN | генератор синтетических данных |

Через ~15 секунд увидите готовый отчёт и заключение локальной модели.
Наслаждайтесь зрелищем.

Остановка: закройте окна или Ctrl+C в окнах watcher / gen.

## Что требуется ДО запуска (это делает opencode по скиллу)

1. **Python 3.10+** (проверьте: `python3 --version`).
2. **LM Studio** (бесплатно, https://lmstudio.ai) с загруженной моделью
   **Qwen2.5-1.5B-Instruct** (GGUF `qwen2.5-1.5b-instruct-q4_k_m.gguf`,
   репо `Qwen/Qwen2.5-1.5B-Instruct-GGUF`) и поднятым локальным сервером
   на `127.0.0.1:1234`.
3. **Режим мышления (reasoning) ВЫКЛЮЧЕН** — для Qwen2.5 это неактуально
   (модель не reasoning), но убедитесь, что в LM Studio не включён никакой
   thinking-режим.
4. Имя модели уже прописано в `project_stat/script/config.py`
   (`AI_MODEL_ANALYTICS = "qwen2.5-1.5b-instruct"`) — менять не нужно.

> Если LM Studio не поднят — стенд всё равно работает, но ИИ-блок выдаёт
> «ИИ недоступен». Расчёт и отчёт работают без модели.

## Структура репо

```
magic_share/
├── magic_share.md     # СКИЛЛ для opencode (runbook подготовки)
├── README.md          # эта инструкция
├── run.bat            # Windows-лончер (из корня НЕ запускать — только из project_stat/)
├── run.sh             # macOS/Linux-лончер
├── layout.ps1         # раскладка 2×2 (Windows)
├── layout_mac.scpt    # раскладка 2×2 (macOS)
└── project_stat/      # сам стенд
    ├── script/*.py    # server, watcher, gen_test_data, analytics, ai_client, ...
    ├── workflow/ui.html
    ├── infographic/   # референсные отчёты
    └── ПРЕЗЕНТАЦИЯ.md
```

Запускайте `run.bat`/`run.sh` строго изнутри `project_stat/` (они сами
переходят в `script/`).

## Откуда данные

Генератор `gen_test_data.py --seed 42` детерминированно синтезирует 40 CSV
(10 партий × 4 участка) прямо при запуске — никаких внешних файлов не
нужно. Watcher «оживает» на живую генерацию, как в реальном цеху.

## Почему 1.5B, а не 9B

Лёгкая модель поднимается на слабых машинах и демонстрирует силу локальных
LLM без тяжёлого железа. Расчёт всё равно детерминированный (в
`analytics.py`); модель только интерпретирует уже посчитанные числа. Если
хотите точнее текст — замените модель на `qwen2.5-3b`/`qwen2.5-7b` (или
`qwen3.5-9b`) в `config.py` и поднимите `AI_TIMEOUT`/`AI_MAX_TOKENS`.
