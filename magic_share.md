# magic_share — skill для opencode

## Что этот скилл делает (и чего НЕ делает)

Этот скилл — **runbook для LLM-агента** (opencode). Твоя задача при его
исполнении: подготовить рабочую папку коллеги так, чтобы он потом ОДНОЙ
командой (`run.bat` на Windows / `run.sh` на Mac-Linux) поднял весь
демо-стенд project_stat и увидел «зрелище»: живой генератор данных →
watcher → аналитика → отчёт в браузере + локальная LLM, которая на русском
объясняет результат.

Ты **НЕ запускаешь** `run.bat`/`run.sh` сам и **НЕ генерируешь** данные.
Ты только готовишь окружение и говоришь человеку: «Готово, запусти
`run.bat`». Запуск стенда — за человеком (это часть «зрелища»).

---

## ⚠️ ЖЁСТКИЕ ПРАВИЛА (нарушение = провал скилла)

1. **НИКАКИХ действий без явного разрешения пользователя** на шагах,
   помеченных `PERMISSION REQUIRED`. Спрашивай до действия, не после.
2. **Изменяй только рабочую папку** (ту, что открыта в opencode-сессии).
   Ничего не трогай в системе вне неё.
3. **Не удаляй и не перезаписывай** пользовательские файлы без согласия.
4. **Пиши пользователю по-русски**, коротко, по делу. Сообщай, что делаешь
   ДО и ПОСЛЕ каждого шага (принцип «обозначай свои действия»).
5. Если шаг не удался — скажи прямо, что именно, и предложи альтернативу.
   Не имитируй успех.

## Вводные данные (фиксированные)

- **GitHub-репо:** `https://github.com/multifather/magic_share`
- **Папка назначения в репо:** `project_stat/` (внутри рабочей папки
  opencode). Человек запускает `project_stat/run.bat` (Win) или
  `project_stat/run.sh` (Mac/Linux).
- **Локальная LLM:** Qwen3.5-**1.5B** (лёгкая лингвистическая модель),
  OpenAI-совместимый эндпоинт LM Studio на `http://127.0.0.1:1234/v1`.
- **Режим мышления (reasoning): ВЫКЛЮЧЕН** — обязательное требование
  (иначе модель «допересчитывает» числа вопреки инструкции и платит 2× латентностью).

## ПОТОК ИСПОЛНЕНИЯ

### Шаг 0. Контекст
Сообщи человеку: «Я выполняю скилл magic_share. Подготовлю твою папку
`<рабочая_папка>` к запуску демо-стенда project_stat. Буду спрашивать
разрешение перед каждым важным шагом.»

Определи ОС:
- `uname` / `ver` → Windows / macOS / Linux.
- Запомни ОС, она влияет на лончер (`run.bat` vs `run.sh`) и пути.

---

### Шаг 1. Клонировать репо
`PERMISSION REQUIRED` — скажи: «Мне нужно клонировать репо
`https://github.com/multifather/magic_share` в твою рабочую папку
(`<рабочая_папка>`). Разрешаешь? Это создаст папку `project_stat/` с кодом
стенда.»

После разрешения:
```
cd <рабочая_папка>
git clone https://github.com/multifather/magic_share _ms_tmp
# клонируем в подпапку, т.к. в рабочей папке уже лежит этот skill-файл
# и git clone в непустую папку упадёт
cp -r _ms_tmp/. <рабочая_папка>/
rm -rf _ms_tmp
```
Если `git` недоступен — скажи человеку поставить git и повторить, либо
предложи скачать ZIP с GitHub и распаковать вручную (НЕ делай это без
разрешения).

`CHECK`: убедись, что появился `<рабочая_папка>/project_stat/script/server.py`.

---

### Шаг 2. Проверить Python
```
python3 --version   # или python --version
```
`PERMISSION REQUIRED` только если Python НЕТ: «Для стенда нужен Python 3.10+.
Его нет. Разрешаешь, я подскажу, как поставить (python.org / brew / apt)?»
Сам ничего не ставь без разрешения. Если Python есть (3.10+) — иди дальше.

`CHECK`: `python3 --version` выдаёт 3.10+.

### Шаг 3. Подготовить локальную LLM (Qwen3.5-1.5B)
Это самый «тяжёлый» и критичный шаг. Без него стенд поднимется, но ИИ-блок
будет выдавать «ИИ недоступен».

`PERMISSION REQUIRED` — скажи: «Стенду нужна локальная модель
Qwen3.5-1.5B и LM Studio (бесплатно). Я проверю, установлена ли LM Studio;
если нет — направлю тебя на установку и скачивание модели (~1 ГБ). Разрешаешь
двигаться в этом направлении?»

После разрешения — ПОШАГОВО (каждое поддействие тоже с подтверждением):

1. **Проверка LM Studio:**
   - Windows: есть ли `C:\Users\<user>\AppData\Local\LM Studio\...` или
     процесс `LM Studio` в Диспетчере задач.
   - macOS: `/Applications/LM Studio.app` или `lm-studio` в PATH.
   - Linux: `lm-studio` в PATH / `/opt`.
   Если нет — скажи: «Поставь LM Studio: https://lmstudio.ai (бесплатно).
   Это нужно сделать вручную, я не могу установить GUI-приложение за тебя.»
   ЖДИ, пока человек поставит. Не имитируй.

2. **Модель Qwen3.5-1.5B:**
   - В LM Studio → Discover → найти `qwen3.5` (или `Qwen3.5-1.5B`).
   - Если точное имя в твоём источнике иное (напр. `qwen3.5-1.5b-instruct`
     или GGUF-конверсия) — используй то, что реально доступно.
   - Скачай (~1 ГБ). `PERMISSION REQUIRED`: «Скачиваю модель ~1 ГБ. Ок?»
   - Загрузи модель в LM Studio (Load).

3. **Поднять локальный сервер:**
   - В LM Studio → Developer / Local Server → Start server на
     `127.0.0.1:1234`.
   - `CHECK`: `curl -s http://127.0.0.1:1234/v1/models` возвращает JSON с
     моделью. Если нет — скажи человеку поднять сервер вручную.

4. **ВЫКЛЮЧИТЬ режим мышления (критично!):**
   - В настройках LM Studio сервера убедись, что reasoning/mthinking ВЫКЛ.
   - `CHECK`: модель отвечает без длинного «thinking»-блока.
   - Это дублируется в коде (`config.py`: `AI_ENABLE_THINKING = False` +
     `ai_client.py` шлёт `enable_thinking: false`), но на стороне LM Studio
     тоже должно быть выключено — иначе латентность 2×.

5. **Запомнить ТОЧНОЕ имя модели:**
   - Из ответа `/v1/models` возьми поле `id` загруженной модели
     (напр. `qwen/qwen3.5-1.5b` или `qwen3.5-1.5b-GGUF`).
   - Это имя нужно прописать в `config.py` (см. Шаг 4).

---

### Шаг 4. Адаптировать config.py под точное имя модели
В `<рабочая_папка>/project_stat/script/config.py` уже стоит:
```
AI_MODEL_ANALYTICS = "qwen/qwen3.5-3b"   # СТАВЬ МОДЕЛЬ 1.5B В LM STUDIO
AI_MODEL_CHAT      = "qwen/qwen3.5-3b"
AI_ENABLE_THINKING = False
```
`PERMISSION REQUIRED` — скажи: «Подставлю в config.py точное имя модели,
которое ты загрузил в LM Studio: `<id_из_шага_3>`. Изменю только эти две
строки. Разрешаешь?»

После разрешения — замени оба `AI_MODEL_*` на `<id_из_шага_3>`.
Например, если модель `qwen/qwen3.5-1.5b`:
```
AI_MODEL_ANALYTICS = "qwen/qwen3.5-1.5b"
AI_MODEL_CHAT      = "qwen/qwen3.5-1.5b"
```
`CHECK`: `grep AI_MODEL <рабочая_папка>/project_stat/script/config.py`
показывает нужное имя.

> Примечание: `AI_ENABLE_THINKING = False` и `AI_TEMPERATURE = 0.2` уже
> выставлены под лёгкую модель. Не меняй их без явной нужды.

Сообщи человеку сводку:
- [x] Репо клонировано в `<рабочая_папка>/project_stat/`
- [x] Python 3.10+ есть

- [x] Локальный сервер :1234 поднят, thinking OFF

## Что делать, если что-то пошло не так

- **LM Studio недоступен / не ставится:** стенд всё равно запустится,
  но ИИ-блок скажет «ИИ недоступен» — расчёт и отчёт работают без него.
  Скажи об этом человеку честно.
- **Модель не грузится / не тот id:** вернись к Шагу 3.4, возьми реальный
  `id` из `/v1/models`, повтори Шаг 4.
- **Git clone упал:** проверь сеть / наличие git; предложи ZIP-скачивание.
- **Python < 3.10:** стенд не запустится; направь на обновление Python.

## Почему именно так (коротко)

- **1.5B, а не 9b:** лёгкая модель поднимается на слабых машинах коллег,
  демонстрирует силу локальных LLM без тяжёлого железа. Цена — проще
  текстовый вывод; расчёт всё равно детерминированный (в analytics.py),
  модель только интерпретирует.
- **Thinking OFF:** reasoning-модель Qwen3.5 без выключенного мышления
  «допересчитывает» числа и платит 2× латентностью на iGPU.
- **Клон в project_stat/:** стенд самодостаточен, запускается из своей
  папки; рабочая папка opencode остаётся чистой.
- **Все действия — с разрешения:** это требование заказчика (явные
  permission-запросы opencode), чтобы человек контролировал установку
  ПО, скачивание ГБ-модели и запуск локальных серверов.
