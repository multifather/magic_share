## Исходный запрос (2026-08-07)

Пользователь хочет поделиться своим проектом `project_stat` (автономный
аналитический стенд паркетной фабрики) с коллегами. Механика:

- Коллега уже поставил **opencode**.
- Открывает opencode, новая сессия в пустой рабочей папке, скачивает
  **skill `magic_share.md`**, пишет «выполни skill magic_share.md».
- opencode по скиллу воссоздаёт всю архитектуру `project_stat` у коллеги:
  забирает данные, поднимает **локальную LLM Qwen3.5-1.5B** через LM Studio,
  **выключает режим мышления**, адаптирует конфиг.
- Итоговый уровень: «скачал файл → запустил → наслаждаешься зрелищем».
- opencode при взаимодействии **явно запрашивает все критические разрешения**
  и обозначает свои действия.

Базовая папка `project_stat` — только чтение, ничего не меняем.
Рабочая папка `/magic_share` (создана, т.к. в песочнице отсутствовала).

## Решения

- **Рабочая папка** `/magic_share` = `D:\for_hermes\magic_share`. База
  `project_stat` = `D:\for_hermes\project_stat` (read-only, трогать нельзя).
- **Вводные данные** = генератор `gen_test_data.py --seed 42` (детерминированно
  40 CSV, 10 партий). Watcher «оживает» на живую генерацию, как в цеху.
  Никаких внешних файлов не нужно.
- **Модель**: **Qwen2.5-1.5B-Instruct** (GGUF, q4_k_m) — реально доступна как
  готовый GGUF для LM Studio. Имя захардкожено в `config.py`
  (`AI_MODEL_ANALYTICS = "qwen2.5-1.5b-instruct"`). Плейсхолдер `qwen3.5-3b`
  убран. URL для скачивания в LM Studio прописан в `config.py`
  (`LM_STUDIO_MODEL_DOWNLOAD_URL`).
- **Thinking OFF**: уже реализовано в базе (`config.AI_ENABLE_THINKING=False`
  + `ai_client` шлёт `enable_thinking:false`); opencode только подтверждает,
  что LM Studio не включает reasoning.
- **Кроссплатформенность**: коллеги и на Windows, и на Mac. Сделаны
  `run.bat` (Win, браузер по умолчанию вместо жёсткого Firefox) и `run.sh`
  (Mac/Linux) + `layout.ps1` (2×2 Win) и `layout_mac.scpt` (2×2 macOS).
- **Мульти-оконный стенд**: server hidden + watcher + gen + explorer/проводник
  + браузер, раскладка 2×2.
- **Адаптация под 1.5B**: `ai_client.py` — упрощён промпт (`ANALYSIS_TASK`
  сокращён до 3 пунктов с жёстким «не пересчитывай числа»), добавлена
  `temperature=0.2`, `AI_MAX_TOKENS=400`.

## Развилки

- **Модель 1.5B vs 9b**: выбрали 1.5B (подъём на слабых машинах коллег).
  Риск: 1.5B слабее держит длинные инструкции — смягчили промпт и temperature.
- **Точка входа**: коллега УЖЕ поставил opencode → просто клонирует репу и
  дёргает скилл (вариант Б из обсуждения, не bootstrap-файл).
- **Браузер**: браузер по умолчанию, не только Firefox (как в оригинальном
  `run_all.bat` базы) — поправили `layout.ps1` на матч по URL/классу любого
  браузера.
- **LLM для самого opencode**: у коллеги уже подключена бесплатная модель
  (вторая LLM не нужна).
- **Куда клонирует opencode**: в подпапку `project_stat/` корня рабочей папки
  (а не в корень), чтобы стенд был самодостаточен и папка opencode чистой.

## Развороты

- **Структура сначала была плоской**: при первом копировании `project_stat`
  распаковали прямо в корень `/magic_share` (в `script/`, `workflow/`,
  `infographic/`), а скилл инструктировал работать с `project_stat/`.
  Обнаружено при проверке пуша (404 на `project_stat/script/server.py`).
  Перенесли содержимое в `project_stat/`, поправили лончеры.
- **Git index pollution**: после перестройки в индексе остались stale-записи
  старой плоской раскладки (`infographic/`, root `script/`), `git add -A`
  их рестейджил. Лечение: `git rm -r --cached .` + пере-`add` только
  корректных путей, amend + force-push. Финально: 27 файлов, 19 в
  `project_stat/`, ноль flat-root путей.
- **GitHub-авторизация**: `gh` нет, нет ssh/токенов в окружении. В
  `hermes.env` оказалось ДВА токена — `github_pat_...` (fine-grained, БЕЗ
  права создавать репо, 403) и `ghp_...` (classic, с правом — создал репо
  и запушил). Использовали `ghp_`.

Коллега прогнал стенд, два замечания — оба исправлены:

1. **Браузер не ловился раскладкой** — `start "" url` открывал вкладку в

   стенд сейчас (вариант А, opencode запускает `run.bat`/`run.sh` с
   разрешения) или показать инструкцию к самостоятельному запуску

## Баг: run.bat не открывал браузер (2026-08-08)

Коллега прислал точный баг-репорт. Корень — два дефекта в `run.bat`:
1. **Delayed expansion в cmd**: `echo %BROWSER_CMD%` внутри блока `if (...)`
   раскрывалось пустым на этапе разбора блока → `ECHO is on.` →
   `BROWSER_EXE=ECHO` → `start "" "ECHO" --new-window` молча падал.
   В логе: `default browser: ECHO`.
2. **Пути с пробелами**: `for /f "tokens=1"` резал
   `"C:\Program Files\Mozilla Firefox\firefox.exe"` до `C:\Program`.

Фикс: весь резолв вынесен в отдельный `resolve_browser.ps1` (читает ProgId
из реестра → команда запуска → полный путь EXE строго между кавычками, с
fallback на `HKCU\Software\Classes`, с проверкой существования файла).
`run.bat` вызывает `powershell -File resolve_browser.ps1` и берёт вывод в
`BROWSER_EXE` через `for /f "delims="`. Это устраняет оба бага и quote-hell
(PS-код в файле, а не внутри `for /f ('...')`).

**Проверено через `cmd /c`** (рекомендация из репорта): тестовый .bat с
этой логикой выдал `default browser: C:\Program Files\Mozilla Firefox\firefox.exe`
(полный путь с пробелами, без `ECHO`), `RESULT=OK`. macOS/Linux (`run.sh`)
этой проблемы не имеют (`open -n` / `xdg-open` сами ищут браузер).

## Вопросы (resolved)

- **Имя модели в `config.py`** — решено (2026-08-07, уточнение): модель
  **Qwen2.5-1.5B-Instruct** (GGUF q4_k_m) захардкожена. Причина: реальной
  «Qwen3.5-1.5B» не существует (Qwen3.5-серия выпустила 0.8B/2B/4B/9B…, но
  не 1.5B; Qwen3.5-2B идёт только safetensors, требует конвертации в GGUF).
  Qwen2.5-1.5B-Instruct-GGUF — единственная 1.5B Qwen, готовая к LM Studio.
  Имя `qwen2.5-1.5b-instruct` прописано в `config.py` жёстко; URL скачивания
  GGUF — в `LM_STUDIO_MODEL_DOWNLOAD_URL`. opencode скачивает именно её.
- Отчёт `infographic/stat_report_20260806_152058.html` из базы исключён из
  репо (это сгенерённый артефакт, не нужен для работы стенда).
